## 一、字库系统（DATA1\font\）

### 1. 文件构成
| 文件 | 大小 | 内容 |
|---|---|---|
| font_16_a.txt | 21062 B | **二进制**字符映射表（不是文本！），10531 × u16 |
| font_16_a0/a1/a2.ext | 290384 B | 主字库 × 3 种样式，各 2268 字形 |
| font_16_b0/b1/b2.ext | 11088 B | 辅助字库 × 3 种样式，各 86 字形（汉字特效集） |

- a/b = 两个字形库；0/1/2 = 三套渲染样式（调色板 alpha 斜坡不同，字形像素也不同，非简单变色）。
- a 系调色板为纯白 `FFFFFF`，b 系为 `FEFEFE`（微灰）。
- 字形网格 **16×16 像素**，抗锯齿。

### 2. .ext 字形文件格式（引擎称 GIQ 格式，解析函数 Lib_GiqPictureLoadExt @ BOOT.BIN 0x71AB8）
```
0x00  u16 flags    =1 (bit0: 宽度须为 2 的幂)
0x02  u8  bppCode  =2 → 4bpp (0=32bpp 1=16bpp 2=4bpp 3=8bpp)
0x03  u8  pixType  =3
0x04  u16 width    =32      图集宽度(像素)
0x06  u16 height   =18144   图集总高度(像素) (=数据大小/16, 字库=2268字形×8行)
0x08  u32 palOff   =0x10    调色板偏移(相对文件头)
0x0C  u32 pixOff   =0x50    像素数据偏移
0x10  u8  palette[64]       16色 × RGBA8888
0x50  u8  pixels[]          4bpp 调色板索引，每字节左右两个像素(高半字节=左)
```
- **调色板 = 抗锯齿等级表**：索引 0 = 全透明，索引 5 = alpha 0xFF（实色墨迹），其余为 14 级过渡 alpha。三个样式文件就是斜坡不一样。
- **字形定位（关键）**：图集宽 32px，一行放 2 个 16×16 字形。字形 g：
  `band = g >> 1`（第几个 256 字节带），`half = g & 1`（左/右半），
  行 r 的字节偏移 = `0x50 + band*0x100 + r*0x10 + half*8`
- 字形数 = `(文件大小 - 0x50) / 128`。

### 3. 字符映射 font_16_a.txt（游戏文本 → 字形 的桥梁）
```
index = JIS 码线性化: ((JIS高字节-0x21)*96 + (JIS低字节-0x21))
        半角 ASCII 直接用字节值做 index
value = 字形编号 (0..2267)
```
10531 项覆盖 JIS 0x21~0x8B 行。共 2263 个有效映射。

### 4. 整条渲染链路（已实证）
```
脚本文本(Unicode UTF-16)
  → CCC\ucs2jis.bin (65536×u16, Unicode→JIS原码, ASCII恒等)
  → 线性化成 font_16_a.txt 的 index
  → 查表得字形号 g
  → .ext 图集取字形绘制
CCC\jis2ucs.bin (65536×u16) 是反向表(JIS原码→Unicode), 供存档/系统界面用
```
验证样例：る(U+308B)→JIS 246B→idx 362→字形49 ✓、ろ→字形141 ✓、か→字形1773 ✓、A→字形1851 ✓

### 5. 汉化要点
- **改字形**：PNG 编辑后用 `ext_font.py import` 写回（已测字节级无损回环）。
  6 个文件都要同步改（或至少改用到的样式）。
- **加字形**：图集可纵向扩展（height 字段 + 文件尾追加 256B/2字形的带）。
- **补映射**：ucs2jis.bin 中约 19% 常用简体字无 JIS 映射（值为 0）。
  cmap 第 8064~10530 槽（JIS 0x75 行以后）当前全空 —— 把缺的简体字指到空闲 JIS 码位，
  同步改 ucs2jis.bin + jis2ucs.bin + cmap + 字库即可，**不需要动 EBOOT**。
- b 系列（86 汉字）无独立 cmap，其字形内容与 a 系前 86 号不同，用途为特定 UI 特效字。

## 二、图片（DATA1\visual\，5785 个 .pac + 35 个 .ext + 46 个 .gim）

### 1. .gim — 标准 PSP GIM（`MIG.00.1PSP`），不赘述。

### 2. 独立 .ext — 与字库同格式（GIQ），35 个全部为 8bpp/ptype3 调色板图。

### 3. .pac 结构（全部 5785 个已验证解析）
```
0x00 u8 flag0   0x00=普通 / 0x02=链式(每段前多 0x24 字节段头)
0x01 u8 flag1   0x01 / 0x02 / 0x03 变体标记
0x02 u16 parts  段数(通常 1; sel_title/music_title=2 是超 512 高的图拆两段)
0x04 u16 srcW, srcH      源图尺寸
0x08 u16 dispW, dispH    显示尺寸(PSP 屏 480×272 的裁剪区)
0x0C u32 0
0x10 u32 0
0x14 u32 dispW-1, dispH-1
0x1C u32 fileSize        整个 pac 大小(自校验字段, 重打包必须改)
0x20 u32 0
0x24 [链式段头(仅 flag=2,2)] + GIQ EXT 图像(8bpp: 头0x14 + 调色板0x400 + 像素)
```
- 主体是 **8bpp 256 色 RGBA8888 调色板图**（90%+ 文件）；其余为多段。
- EXT `flags bit0` 表示 PSP swizzle；像素按 16 字节 × 8 行块存放，PNG 导出时必须
  unswizzle，回包时必须重新 swizzle。字库宽度恰为一个 4bpp 块，故其行布局表面上看似线性。
- 多段变体：超高图按 512 行拆段（bg_016 等 270 个）、battle/field 带附加小图（34 个）等。
- 宽度必须 4bpp 时 32 倍、8bpp 时 4 倍对齐（引擎有校验，错误会弹 m_PixBit4 等错误）。
- 解包：`PAC e <输入PAC文件夹> <输出图片文件夹>`。
- 回包：`PAC i <图片文件夹> <输出PAC文件夹>`。
- 已全量扫描验证 5785/5785：5474 个单图、310 个双图、1 个三图，零失败。
  普通、多 EXT、嵌套 PAC 的无修改回包均与原文件 SHA-256 一致；未知附加段原样保留。

### 4. 尺寸校验公式（8bpp 单段）
`文件大小 = 0x24 + 0x410 + W×H`（0x410 = 0x14 头 + 0x400 调色板）

## 三、BOOT.BIN 相关
- 解密后 ELF，程序头 vaddr=0，运行基址 0x08900000（重定位模块，内部指针/jal 全是 0 基）。
- 文件偏移 = vaddr + 0xC0。
- 关键函数：
  - `Lib_FontSetCB` ≈ 0x6BCE4 字体加载状态机（读 jis2ucs/ucs2jis/font_16_a.txt + font_16_[ab]%d.ext）
  - `Lib_GiqPictureLoadExt` = 0x71AB8（.ext 图像/字库通用解析器）
  - sprintf "font_16_a%d.ext" @ 0x252B0 附近

## 四、CCC 编码表的身份（已官方实锤）

`CCC\jis2ucs.bin`、`CCC\ucs2jis.bin` 与 pspautotests（PPSSPP 官方测试集）
`tests\ccc\` 里的同名文件 **MD5 逐字节一致**（5aa0e060…/90c20ec6…）。

即：这两个表是 **PSP SDK 标准表**，由系统字符转换库 **sceCcc（libccc.prx）** 消费：
游戏加载两表 → `sceCccSetTable(jis2ucs, ucs2jis)` 注册 → 之后 SJIS↔Unicode
转换全部查表（UTF8↔UTF16 不需要表，纯算法）。

对本项目意味着：
1. 游戏在编码层没做任何私有魔改，原表 = 原厂标准表，无隐藏惊喜。
2. 改 `DATA1\CCC\` 两表即改变全部文字映射，不需要动 EBOOT。
3. PPSSPP 对 sceCcc 做了 HLE 且使用游戏注册的表 → 改表后在模拟器上直接生效可测。
4. `tools\pspautotests-...\tests\ccc\convertstring.cpp` 可当官方语义文档查阅。
5. 零/碧轨迹 PSP 汉化改的正是这套标准表（其仓库 tools/cn_psp_sjis 附带改了
   1296 槽位的版本），同一改造路线已有成功先例。
